## 2. 这篇文献研究了什么问题？

### Research question / aim

本文的核心目标是提出一个适合 **移动端实时运行** 的单人身体姿态估计系统。作者提出 **BlazePose**，一种轻量级卷积神经网络架构，用于在手机等设备上进行实时人体关键点检测与追踪。摘要中说明，该系统在推理阶段输出 **33 个身体关键点**，并能在 Pixel 2 手机上达到实时性能。

### 为什么这个问题重要？

作者在 Introduction 中指出，人体姿态估计可用于 **health tracking、sign language recognition、gestural control** 等应用，但该任务受到姿态多样性、人体自由度高、遮挡等因素影响，具有挑战性。传统 heatmap-based 方法精度较好，但对于单人移动端实时推理来说模型较大、计算开销较高。

### 3.4 实验流程

| 阶段                 | 方法                                                                                             |
| ------------------ | ---------------------------------------------------------------------------------------------- |
| Inference pipeline | detector-tracker setup，见 Figure 1                                                              |
| Detection          | 使用 lightweight body pose detector；作者实际采用 fast on-device face detector 作为 person detector proxy |
| Alignment          | detector 预测 hip midpoint、人体外接圆大小、incline angle                                                 |
| Tracking           | tracker 预测 keypoint coordinates、person presence、refined ROI                                    |
| Re-detection       | 当 tracker 判断当前帧无人时，下一帧重新运行 detector                                                            |
| Training           | 使用 heatmap、offset、regression 联合训练                                                              |
| Inference          | 推理时移除 heatmap / offset 输出层，仅保留坐标回归相关部分                                                         |
| Occlusion handling | 使用随机矩形遮挡增强，并引入 per-point visibility classifier                                                 |
| Evaluation         | 与 OpenPose 对比；使用 FPS 和 PCK@0.2                                                                 |

### 3.5 算法或统计方法

本文不是统计验证型论文，而是算法 / 系统方法论文。主要方法包括：

1. **Detector-tracker pipeline**
   先检测人体区域，再追踪关键点和 ROI。这样可以减少每帧重新检测的开销。

2. **Face detector as proxy for person detector**
   作者认为 face 对网络定位 torso 有强信号，因此使用 fast on-device face detector 作为 person detector proxy。
   但这依赖一个重要假设：**single-person AR use case 中 head should always be visible**。这对你的坐姿场景很重要，因为如果头部离开画面或遮挡，检测可能受影响。

3. **33 keypoint topology**
   作者构建了 33 点人体拓扑，是 BlazeFace、BlazePalm、COCO 关键点的 superset。Appendix A 中包含 left ear、right ear、left shoulder、right shoulder、left hip、right hip 等与你的 CVA 和躯干姿态计算相关的关键点。

4. **Training with heatmaps, inference with regression**
   训练阶段使用 heatmap 和 offset loss 辅助学习；推理阶段删除对应输出层，用 regression encoder 直接输出坐标。这是本文提升移动端速度的关键设计之一。

5. **Occlusion augmentation + visibility classifier**
   作者通过随机矩形模拟遮挡，并为每个点引入 visibility classifier，用于判断关键点是否被遮挡或预测是否不可靠。

### 3.6 Ground truth 是什么？

本文的 ground truth 是 **人工标注的关键点坐标**。
文中没有使用 RGB-D sensor、motion capture、深度相机或临床量角器作为 ground truth。

对你的项目而言，这一点很关键：
**本文可以支持“BlazePose/MediaPipe Pose 适合移动端实时关键点提取”的论据，但不能作为“单目估计 CVA 或 head pitch 对 RGB-D ground truth 精确可靠”的证据。**

可以用于讨论：

* 轻量级 pose estimator 适合实时系统，但关键点检测准确性不等于临床姿态指标准确性；
